Methodology & privacy

How the model works, what is verified and what is not, and the privacy rules this desk follows.

Model method

  • Projections are derived, not predicted. Every figure is computed from labelled inputs (growth, return, carrying cost, tax rate). None is a forecast.
  • Model runs on points for display; ranges are recommended. Baseline ranges: house-price growth 3%–6%/yr, portfolio return 4%–8%/yr, inflation 2%–4%/yr. Run the model on ranges (suggestion S16).
  • Money is rounded to the nearest $10. Statutory amounts, rates, and thresholds are quoted exactly as published and marked exact; rounding a legal threshold would misstate it.
  • Every table row carries a source link or is blank and marked unverified / owner-supplied / derived. No inferred or invented values.
  • After any input change, rebuild the model and check whether the recommendation moved. Re-run annually with updated inputs [question Q26].
  • Extreme scenarios reviewed annually. Black-swan regimes (1929 −89%, 2008 −57%) and phased-investing path (Treasuries 24–36 months) stress-test the sell option.

Privacy rules

  • No names, street addresses, parcel numbers, ZIP codes, city names, neighbourhood names, phone numbers, e-mail addresses, or account figures appear on this desk.
  • Properties are "Property A" (future trust inheritance, Santa Clara County) and "Property B" (already owned, San Francisco County) at county level only.
  • Owner-supplied values (market value, rent, insurance, utilities, assessed value) are labelled owner-supplied and unverified, and are not traced to any official record.
  • No assessment or tax-bill history series is published at any precision — a rounded series can still match one parcel against open assessor rolls.
  • Personal information collected during research is for internal use only and must not appear on this desk.

Pre-rounding exposure (flag F16)

Earlier public-data exposure. Earlier generations of this repository may retain unrounded owner-provided tax and property values in public Git history. A normal PR cannot remove those commits. This is a limitation, not a claim that history is clean. The repository maintainer must decide on a coordinated history rewrite and/or repository-visibility response. [flag F16]
